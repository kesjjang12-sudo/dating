# 연분 추천 알고리즘 — 오늘의 인연은 어떻게 뽑히나

> 코드 위치: 후보 선정 `mobile/src/lib/store.ts`(`buildDeck`), 궁합 계산 `mobile/src/lib/saju/compat.ts`,
> 사주 산출 `mobile/src/lib/saju/manseryeok.ts`. 전 과정이 **결정론적**(같은 입력 → 항상 같은 결과)이라
> 재현·검증이 가능하고, "왜 이 사람이 추천됐는지"를 점수 근거로 설명할 수 있다.

## 한 줄 요약

**후보군(이성 전원)을 궁합 점수로 정렬하고, 날짜 기반 회전으로 매일 3명을 뽑는다.**
궁합은 필터가 아니라 정렬이다 — 점수가 낮다고 배제되진 않고, 순서가 뒤로 갈 뿐이다.

## 1단계 — 후보군 만들기

서버(Supabase `profiles` 테이블)에서 **실유저 + 시드 프로필 전원**을 불러온 뒤 다음만 제외한다.

| 제외 대상 | 이유 |
|---|---|
| 동성 프로필 | 이성 매칭 서비스 가정 |
| 나 자신 (`auth` 계정의 handle) | 실유저는 자기 프로필이 서버에 있으므로 |
| 이미 매칭된 상대 | 중복 추천 방지 |
| 내가 "지나가기"한 상대 | 의사 표시 존중 |
| 추가 열람 시 현재 덱에 있던 상대 | 같은 날 중복 방지 |

나이·거리 제한은 아직 없다(아래 "다음 단계" 참고). 실유저가 가입하면 즉시 다른 유저의 후보군에 들어간다.

## 2단계 — 궁합 점수 (0~100)

두 사람의 사주(연·월·일·시 4주, 시간 미상이면 3주)를 만세력 엔진으로 계산한 뒤,
5개 요소를 각각 0~100으로 채점하고 가중 평균한다.

| # | 요소 | 가중치 | 채점 규칙 (대표값) |
|---|---|---|---|
| 1 | 오행 상생 | **0.28** | 일간 오행이 상생 90 / 비화 72 / 상극 58, 상대가 내 결핍 오행을 채우면 +3/개 (최대 +10) |
| 2 | 일간 궁합 | **0.24** | 천간합(갑기·을경·병신·정임·무계) 95 / 상생 82 / 비화 68 / 상극 56, 음양이 다르면 +5 |
| 3 | 지지 합·충 | **0.22** | 일지 육합 92 / 삼합 86 / 같은 지지 74 / 무관 70 / 충 45, 월지 합 +5·충 −5 |
| 4 | 띠 궁합 | **0.14** | 연지 삼합 90 / 육합 88 / 같은 띠 76 / 무관 72 / 충 50 |
| 5 | 음양 균형 | **0.12** | 두 사주의 양(陽) 비율 합이 1에 가까울수록 높음 (서로 보완 구조) |

- **정밀 궁합 배지**: 양쪽 모두 출생시간이 있으면 시주까지 포함해 계산되고 "정밀" 표시가 붙는다.
- 카드의 한 줄 풀이("임정합 — 서로를 길들이며…")와 상세 풀이도 같은 규칙에서 템플릿으로 생성된다.
- 사주 산출 자체는 만세력 기준: 절기(입춘 경계 포함)는 태양 황경 계산으로 1920~2040년을 커버하며
  한국천문연구원 값과 ±2~6분 이내로 검증됐다 (`mobile/scripts/verify-saju.ts`, 23개 검증 통과).

## 3단계 — 매일 3명 선택 (날짜 회전)

1. 후보군을 궁합 총점 내림차순으로 정렬
2. `1970년 기준 경과일 % 후보 수`만큼 시작점을 회전 → **매일 다른 구간이 노출 기회를 얻는다**
3. 회전된 목록을 다시 궁합순으로 정렬해 **상위 3명**을 오늘의 덱으로 확정
4. 자정(날짜 변경)마다 새로 계산, "인연 3명 더 보기"(엽전)는 현재 덱을 제외하고 같은 로직 재실행

회전을 넣은 이유: 순수 궁합순만 쓰면 최고 궁합 몇 명이 모든 유저에게 반복 노출돼
소수에게 신호가 쏠린다. 날짜 회전이 노출을 분산시키되, 재정렬로 "그날 후보 중 궁합 최상위"는 유지한다.

## 수익 장치와의 연결

- 신호 보내기(엽전 50) → 서버 원장(`ledger`) 기입 → 수락 시 매칭 생성 (DB 트리거)
- 상세 궁합 풀이(엽전 30), 추가 덱(엽전 20), 조회자 확인(엽전 60) — 모두 서버 RPC로 차감
- 즉 **추천 → 신호 → 매칭 → 채팅 → 얼굴 공개** 전 구간이 서버에 기록돼 운영 지표로 추적 가능

## 다음 단계 (기획서 대비 미구현)

기획서(`docs/product-spec.md`)의 노출 순위 공식은
`궁합 0.5 × 활동성 0.2 × 프로필 완성도 0.2 × 거리 0.1`인데, 현재는 **궁합 단일 축 + 날짜 회전**만 구현된 상태다.

| 항목 | 현재 | 계획 |
|---|---|---|
| 활동성 가중치 | 없음 | 최근 접속·응답률 반영 (잠수 계정 노출 하향) |
| 프로필 완성도 | 없음 | 사진·소개·태그 채움 정도 반영 |
| 거리 가중치 | 표시만 (실좌표 하버사인 거리) | 정렬 가중치로 편입 |
| 나이 선호 필터 | 없음 | 온보딩에서 선호 범위 수집 후 필터 |
| 서버사이드 추천 | 클라이언트 계산 | 유저가 늘면 Edge Function으로 이관 (로직은 순수 TS라 그대로 이식 가능) |
